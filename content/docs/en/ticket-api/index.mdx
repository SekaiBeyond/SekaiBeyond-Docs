---
title: Ticket API
description: Sign people in to registered apps, read our events and team, and sell tickets for paid events from another app's server.
---

Two kinds of caller use the API, both under apps registered by core-staff in **Tools > Apps**:

- **A registered app's server, with an API key** ([Apps and API keys](./keys.mdx)): reads every event, the team and any event's staff, and sells tickets for the paid ones. Tickets sold this way go on the event's attendee list and scan at the door like any other. The buyer holds them in that app rather than in an account on the site, so they don't show in anyone's **My Tickets** there. An order can also ask us to email the buyer their tickets.
- **A person signed in to a registered app, with that sign-in's ID token** ([Sign in with Sekai Beyond](./sign-in.mdx)): the app gets the sign-in by trading the one-time code `/authorize` hands back at [`POST /v1/token`](../api-reference/exchange-code.mdx), then calls [`GET /v1/me`](../api-reference/get-me.mdx) from its pages (CORS) or its server to learn who they are here. That's all a sign-in reads: the rest is read with the app's keys.

<Callout type="warn" title="Each side decides who can access the data it holds.">
  A server API key sees events, the team and every event's staff as core-staff do in the admin panel, unpublished events included, so keys go only to our own systems and to partners' servers we trust. Who in the app may see what a key reads, and what people can do inside the app, is up to the app. A person's sign-in only says who they are.
</Callout>

Its events are both kinds the site has, unarchived and archived, each with the site's own fields.

## What it does

| Endpoint | Caller | Scope | What it does |
|---|---|---|---|
| [`POST /v1/token`](../api-reference/exchange-code.mdx) | Code | — | Trade a sign-in code from `/authorize` for a sign-in |
| [`GET /v1/me`](../api-reference/get-me.mdx) | Person | — | Get the signed-in person as they are now |
| [`GET /v1/team`](../api-reference/list-team.mdx) | Key | `team:read` | List president, core-staff and staff |
| [`GET /v1/events`](../api-reference/list-events.mdx) | Key | `events:read` | List events (all, or the ones the key is held to) |
| [`GET /v1/events/{eventId}`](../api-reference/get-event.mdx) | Key | `events:read` | Get one event, such as to check it just before taking payment |
| [`GET /v1/events/{eventId}/staff`](../api-reference/list-event-staff.mdx) | Key | `event-staff:read` | List an event's staff |
| [`POST /v1/events/{eventId}/orders`](../api-reference/create-order.mdx) | Key | `tickets:write` | Issue an order's tickets once it's paid |
| [`GET /v1/events/{eventId}/orders/{orderId}`](../api-reference/get-order.mdx) | Key | `tickets:read` | Get an order, with whether each ticket has been used |

Prices stay in the seller's app, since events don't store them.
