<Endpoint method="POST" path="/v1/token" />

<ApiPage operation="exchangeCode">

Trades the one-time code that `/authorize` hands back to your app (`#code=…&state=…`) for a Firebase custom token for your app's project, which you pass to `signInWithCustomToken`. See [Sign in with Sekai Beyond](../ticket-api/sign-in.mdx) for the whole flow.

It takes no `Authorization` header: the code, together with the code verifier only your app holds, is the credential (PKCE, [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636)). Call it from your app's page on the origin of the redirect URI the code came back to (CORS, at `https://sekaibeyond.com/api/v1/token`), or from your app's server.

- **A code works once.** It's spent the first time it's offered, whatever the outcome, so a code offered again, or first with the wrong verifier, can't be used.
- **A code lasts two minutes.** Trade it as soon as your page loads.
- **The token is made when you trade the code,** with the person's group as it is then, and `mintedAt` set to then. Sign in with it right away: a token works for an hour, but rules that check [`usedPromptly()`](../ticket-api/sign-in.mdx#deciding-who-may-use-your-app) refuse a sign-in started more than 5 minutes after it was made.

## Body

<Params>
<Param name="code" type="string" required>
The `code` from the URL fragment `/authorize` handed back: 43 characters.
</Param>
<Param name="codeVerifier" type="string" required>
The code verifier you made for this sign-in, whose base64url SHA-256 you sent to `/authorize` as `code_challenge`: 43–128 characters of `A-Z`, `a-z`, `0-9`, `-`, `.`, `_` and `~`.
</Param>
</Params>

## Returns

**200** with `{"token": "<custom token>"}`. The token's claims are `app`, `group` and `mintedAt`: see [Token claims and live checks](../ticket-api/sign-in.mdx#token-claims-and-live-checks).

## Errors

| Status | Code | When |
|---|---|---|
| 400 | `invalid-request` | The body isn't a JSON object with a well-formed `code` and `codeVerifier`. |
| 400 | `invalid-code` | The code is unknown, used, expired or offered with the wrong verifier; it was sent from a page on another origin than the one it was handed to; or the app was removed, had sign-in turned off, or no longer lists that redirect URI. Send the person to `/authorize` again. |
| 401 | `session-ended` | The person's sign-ins were ended here after the code was issued, or their account has been deleted. |
| 500 | `sign-in-failed` | The site couldn't sign the token as the app's service account, most likely because the app's project hasn't granted Service Account Token Creator (see [Grant IAM roles](../ticket-api/sign-in.mdx#grant-iam-roles-on-the-apps-project)). |

Plus `404`, `405` and `500 internal`, as any endpoint can return: see [Errors](./errors.mdx). The `Authorization` errors there don't apply here.
