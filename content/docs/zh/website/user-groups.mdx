---
title: 用户组
description: 角色、管理后台权限、活动工作人员、第一位社长与会员资格。
---

官网使用基于角色的用户组，而不是简单的管理员标记。`group` 是一条单纯的角色阶梯，每个用户被分配以下之一（从低到高）：

| 用户组       | 说明                                         |
|--------------|----------------------------------------------|
| `user`       | 新登录用户的默认组                           |
| `staff`      | 工作人员：可以打开管理后台，只读             |
| `core-staff` | 核心成员：可以在管理后台中做出更改           |
| `president`  | 社长：可以做出更改，也可以管理核心成员       |

`staff` 及以上可以打开管理后台。工作人员以只读方式查看所有标签页，但可以处理活动入口（扫码验票和添加现场参会者），且看不到「应用」工具。更改由核心成员和社长做出，包括分配用户组：核心成员可以在 `user` 和 `staff` 之间调整成员，社长可以为除自己以外的任何人分配任何用户组。

## 活动工作人员

**活动工作人员**与 `group` 无关。它是按活动设置的标记 `users/{uid}.eventStaffEvents`，任何用户组的人都可以拥有。即将举行的活动的工作人员可以在管理后台中打开该活动（仅限该活动），处理入口并查看参会者名单。核心成员及以上可以在管理后台中为活动添加或移除工作人员，或生成工作人员码，兑换该码的人即成为该活动的工作人员。活动归档时标记会保留，但管理后台的访问权限随之结束。

## 设置第一位社长

新部署中没有人可以分配用户组，所以第一位 `president` 需要手动设置：

1. 登录官网，让 Firestore 中生成你的用户文档
2. 在 Firebase 控制台 > Firestore > `users` 集合中找到你的文档
3. 添加或修改 `group` 字段，将其设为 `president`

设置好第一位社长后，由社长在官网的**管理后台**中为其他用户分配用户组。在 `npm run dev` 下，请改在 Emulator UI 中设置（见[成为管理员](./emulators.mdx#成为管理员)）。

## 会员资格

**会员资格**与 `group` 无关。它是一个有时限的属性 `users/{uid}.membershipExpiresAt`，当且仅当这个时间戳在未来时，该用户才是会员。任何用户组都可以拥有，所以 `president` 也可以是会员；会员资格也从不会提升或降低任何人的用户组。核心成员及以上可以在管理后台的「用户管理」标签页中授予、延长或撤销会员资格；每次更改都会记录在「操作记录」中。没有定时任务：会员资格通过比较时间戳自然失效。
