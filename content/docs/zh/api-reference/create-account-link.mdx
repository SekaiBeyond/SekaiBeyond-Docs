<Endpoint method="POST" path="/v1/account-links" scope="accounts:link" />

<ApiPage operation="createAccountLink">

把你的应用的用户绑定到绑定码对应的账号。请先[预览](./preview-account-link.mdx)，并让用户确认这是自己的账号。完整流程见[绑定账号](../ticket-api/account-links.mdx)。

绑定还会把之前带有这个 `buyer.appUserId` 的所有订单（见[创建订单](./create-order.mdx)）交给该账号，并为已扫码入场的活动计入出席。绑定会记录在官网的「操作记录」中。

<Callout title="重试是安全的。">
  在绑定码原本的有效期内，为同一用户再次发送同一绑定码，会以 200 返回它已创建的绑定。所以超时后请重新发送。
</Callout>

## 请求体

<Params>
<Param name="code" type="string" required>
用户扫描或输入的绑定码。大小写、空格、横线以及二维码的 `SKBYLINK:` 前缀都会被忽略。
</Param>
<Param name="appUserId" type="string" required>
你的应用为该用户分配的 ID，1–64 个字母、数字、`-` 和 `_`。请始终使用同一个 ID，并在该用户的订单中作为 `buyer.appUserId` 发送。
</Param>
<Param name="nickname" type="string">
用户在你的应用中的昵称，最多 64 个字符。账号的设置页会显示它，让持有者知道自己绑定的是哪个用户。
</Param>
<Param name="unionid" type="string">
用户的微信 UnionID（如果你的应用有）：1–64 个字母、数字、`-` 和 `_`。保存它是为了以后官网支持微信登录时能找到已绑定的账号。它不会在任何地方显示。
</Param>
</Params>

## 返回

**201**，返回新的 [AccountLink](./account-link.mdx)；重试时返回 **200** 和已有的绑定。

## 错误

| 状态码 | 错误码 | 何时出现 |
|---|---|---|
| 400 | `invalid-request` | `appUserId`、`nickname` 或 `unionid` 格式不对。 |
| 403 | `no-seller` | 密钥没有销售方 ID。 |
| 409 | `wechat-already-linked` | 该用户已经绑定了账号。 |
| 409 | `account-already-linked` | 绑定码对应的账号已经绑定了其他用户。 |
| 422 | `invalid-code` | 没有这样一个等待使用的绑定码：输错了、已撤回、已过期，或已用于绑定其他用户。 |
| 429 | `rate-limited` | 该密钥每分钟尝试的绑定码超过 30 个（预览和绑定合计）。`Retry-After` 告知需要等待的秒数。 |

另外还有所有端点都可能返回的错误，见[错误](./errors.mdx)。

</ApiPage>
