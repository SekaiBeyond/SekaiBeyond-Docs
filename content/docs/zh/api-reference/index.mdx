## 基础地址

```
https://api.sekaibeyond.com     （可从中国大陆访问，见中转）
https://sekaibeyond.com/api     （其他地区）
```

两者接受相同的路径，响应方式也相同，只有一点不同：只有 `sekaibeyond.com/api` 会响应网页在浏览器中发起的调用（CORS），中转仅供服务器使用。中转的说明见[从中国大陆调用](../ticket-api/mainland-china.mdx)。

## 身份验证

除一个端点外，每个请求都携带服务器 API 密钥，或已登录某个已登记应用的用户的 Firebase ID 令牌：

```
Authorization: Bearer sbk_…         （服务器 API 密钥）
Authorization: Bearer <idToken>     （已登录用户）
Content-Type: application/json      （仅 POST）
```

- **服务器 API 密钥**（`sbk_…`）由核心成员在管理后台「工具 > 应用」中的已登记应用下创建（见[应用与 API 密钥](../ticket-api/keys.mdx)）。密钥仅限服务器对服务器调用，响应永远不会带有 CORS 头。
- **用户 ID 令牌**来自用户在 `/authorize` 登录已登记的应用（见[使用彼世界账号登录](../ticket-api/sign-in.mdx)）。它只能调用 [`GET /v1/me`](./get-me.mdx)，用于确认用户是谁。应用回调地址所在源的网页可以在浏览器中直接调用它（CORS），应用的服务器也可以调用。
- **唯一的例外** [`POST /v1/token`](./exchange-code.mdx) 不需要 `Authorization` 请求头。应用通过它取得用户的登录：用只有应用持有的 code verifier，把 `/authorize` 交回的一次性登录码兑换成自定义令牌。

## 约定

- **请求和响应都是 JSON**，使用 UTF-8 编码。
- **时间戳**为 UTC 时区的 ISO 8601 格式，例如 `2026-11-14T18:00:00.000Z`；未设置时为 `null`。
- **文本字段**未设置时为 `""`，绝不会是 `null`。每个中文字段（以 `Cn` 结尾）都可能是 `""`，此时官网显示对应的英文字段。
- **字段可能会随时间增加**，请忽略不认识的字段。

## 端点

| 端点 | 调用方 | 权限范围 | 作用 |
|---|---|---|---|
| [`POST /v1/token`](./exchange-code.mdx) | 登录码 | — | 把 `/authorize` 交回的登录码兑换成登录凭证 |
| [`GET /v1/me`](./get-me.mdx) | 登录用户 | — | 获取当前登录用户此刻的信息 |
| [`GET /v1/team`](./list-team.mdx) | 密钥 | `team:read` | 列出社长、核心成员和工作人员 |
| [`GET /v1/events`](./list-events.mdx) | 密钥 | `events:read` | 列出活动（全部，或密钥所限定的活动） |
| [`GET /v1/events/{eventId}`](./get-event.mdx) | 密钥 | `events:read` | 获取单个活动，例如在收款前再确认一次 |
| [`GET /v1/events/{eventId}/staff`](./list-event-staff.mdx) | 密钥 | `event-staff:read` | 列出某个活动的工作人员 |
| [`POST /v1/events/{eventId}/orders`](./create-order.mdx) | 密钥 | `tickets:write` | 订单付款后签发其门票 |
| [`GET /v1/events/{eventId}/orders/{orderId}`](./get-order.mdx) | 密钥 | `tickets:read` | 获取订单，以及每张门票是否已使用 |

返回的对象：

- [Person 对象](./person.mdx)：用户的 `uid`、名称、头像、组别与头衔（绝不含邮箱）
- [Event 对象](./event.mdx)：官网的两类活动（未归档和已归档）及其字段
- [Order 对象](./order.mdx)：订单及其门票

票价保存在销售方的应用中，因为活动本身不存储价格。
