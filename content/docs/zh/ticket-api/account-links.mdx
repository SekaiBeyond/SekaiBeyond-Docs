---
title: 绑定账号
description: 让应用的用户绑定自己的 sekaibeyond.com 账号，在应用中购买的门票就会归到官网账号下。
---

你的应用用自己的方式登录用户，例如微信登录。同时拥有 sekaibeyond.com 账号的用户可以把两者绑定。绑定后，他们在你的应用中购买的门票归该账号所有，无论门票发到哪个邮箱：门票会出现在该账号的「我的门票」中，入口扫码时也会计入该账号参加的活动。你的应用还可以展示该账号的个人主页：徽章、通行证和参加过的活动。

账号仍在官网管理。绑定关系以官网为准，你的应用保存的副本只用于展示。

## 用户如何绑定

<Steps>
<Step>

### 在官网获取绑定码

用户登录 sekaibeyond.com，打开个人主页的「设置」，在「微信」一栏点「获取绑定码」（英文界面为 **Settings → WeChat → Get a binding code**）。官网会显示一个 8 位绑定码，以及内容为 `SKBYLINK:` 加绑定码的二维码。绑定码只能使用一次，10 分钟内有效，重新获取会替换旧的绑定码。

</Step>
<Step>

### 在你的应用中扫码或输入

扫描二维码，或让用户输入绑定码，原样发送即可：大小写、空格、横线和 `SKBYLINK:` 前缀都会被忽略。

</Step>
<Step>

### 让用户确认是谁的账号

用绑定码和你的用户 ID [预览绑定](../api-reference/preview-account-link.mdx)。它返回账号的名称、头像和打码后的邮箱（例如 `l***@gmail.com`），并且不会消耗绑定码。请让用户确认这是自己的账号。

<Callout type="warn" title="不要省略确认这一步。">
  有人可能诱导用户扫描为他自己账号生成的绑定码。一旦绑定，用户购买的一切都会进入那个人的账号。预览就是让用户发现这一点的机会。
</Callout>

</Step>
<Step>

### 绑定

用同一个绑定码[创建绑定](../api-reference/create-account-link.mdx)。它返回账号的 `uid`、名称和头像，供你的应用展示。

</Step>
</Steps>

## 你的用户 ID

`appUserId` 是你的应用为该用户分配的 ID：1–64 个字母、数字、`-` 和 `_`，并且始终保持不变。它和订单号一样按销售方 ID 区分（见 [API 密钥](./keys.mdx)），因此其他应用的用户 `10086` 是另一个人。没有销售方 ID 的旧密钥不能绑定账号，会返回 `403 no-seller`：请换一个带销售方 ID 的密钥。

## 订单

在[每笔订单](../api-reference/create-order.mdx)中都发送 `buyer.appUserId`，无论用户是否已绑定：

- **已绑定**：订单立即归该账号所有。
- **尚未绑定**：用户绑定时订单才归到账号下。绑定会把该 ID 之前的所有订单交给账号，并为已扫码入场的活动计入出席。
- **之后解绑**：已经归到账号下的订单仍归该账号，因为它们是为该账号购买的；解绑后的新订单则不再归它。

## 保持同步

双方都可以解绑：用户在官网的设置中解绑，或你的应用通过[删除绑定](../api-reference/delete-account-link.mdx)解绑。官网不会通知你的应用，所以请在用户打开展示绑定的页面时[获取绑定](../api-reference/get-account-link.mdx)，并把 `404 not-linked` 视为未绑定。连不上官网时，展示上一次得到的结果即可。

每一方只能绑定一次：一个用户只能绑定一个账号，一个账号也只能绑定一个用户。要换绑，需要先解绑。绑定和解绑都会记录在官网的「操作记录」中。

## 个人主页

[获取个人主页](../api-reference/get-account-profile.mdx)，即可展示该账号的徽章、通行证和活动及其名称与图片，与账号持有者在自己的个人主页上看到的一样。只把它展示给该用户本人：它不受持有者为他人设置的隐私开关影响。每次调用都会重新读取，请缓存几分钟。

其中的图片由 Google 的服务器提供（Firebase Storage 和 Google 头像），在中国大陆无法加载。

## 权限范围与限制

这里的每个调用都需要 `accounts:link` 权限范围。预览和绑定合计，每个密钥每分钟最多尝试 **30 个绑定码**，这是在每个密钥每分钟 120 次调用之外的单独限制。
