---
title: 使用彼世界账号登录
description: 让用户使用彼世界账号登录你的 Firebase 应用，并代表他们调用 API。
---

SKBY Manager 等已登记的应用可以让用户使用自己的彼世界账号登录。应用无需与主站共用数据库：`issueAppToken` 会通过 IAM 以该应用自己的服务账号身份，**为该应用自己的 Firebase 项目**签发自定义令牌（Custom Token），因此无需保存任何服务账号密钥文件。

- **主站**告诉应用某人是谁，并决定该用户能通过应用读取*主站*的哪些数据。
- **应用**保存自己的数据，并在自己的数据库与安全规则中决定谁能在应用内做什么。

任何已登录的本站账号都可以登录任何开启了用户登录的已登记应用，因此谁可以使用应用由应用自己决定：见[决定谁可以使用你的应用](#决定谁可以使用你的应用)。

<Steps>
<Step>

### 登记应用

在管理后台的「工具 > 应用」中登记应用，并保持勾选「用户用本站账号登录此应用」：

- **回调地址**（`redirectUris`）：1–10 个登录后可返回的地址（须为 `https://`，本地测试可用 `http://localhost` 或 `http://127.0.0.1`，且不含 `#fragment`）。这些站点上的页面也可以在浏览器中直接调用 `/api/v1`（CORS）。
- **可为登录者读取的内容**（可选）：`events:read`、`team:read`、`event-staff:read`。无需任何权限范围，所有应用都能通过 [`GET /v1/me`](../api-reference/get-me.mdx) 获取登录者的名称、头像和组别。
- **Firebase 项目 ID** 与 **服务账号**：该应用自己的 Firebase 项目 ID（例如 `skby-manager`）以及用于签名登录凭证的服务账号（通常是其 `firebase-adminsdk` 服务账号）。

</Step>
<Step>

### 在应用的项目上授予 IAM 角色

展开「工具 > 应用」中该应用卡片下的「负责人设置说明」，在应用的 GCP/Firebase 项目中执行一次上面显示的两条 `gcloud` 命令：

1. 在应用的服务账号上授予 `roles/iam.serviceAccountTokenCreator`，以便我们的函数为该应用的项目签名自定义令牌。
2. 在应用的项目上授予 `roles/firebaseauth.admin`，以便用户在本站退出所有设备、修改密码、撤销邮箱变更或注销账号时，也能同步吊销或删除该应用项目中的对应用户。

登录需要第一项：授予之前，在 `/authorize` 点击「继续」会失败。没有第二项时登录仍可用，但用户在本站的登录被终止时，应用自己的项目不会得到通知。

</Step>
<Step>

### 将用户引导至 `/authorize`

将浏览器跳转至：

```
https://sekaibeyond.com/authorize?app=<appId>&state=<state>&redirect_uri=<redirectUri>
```

- `app`：应用 ID。
- `state`：16–128 个字符（仅限 `A-Z`、`a-z`、`0-9`、`_` 和 `-`），每次发起登录时随机生成并保存在 `sessionStorage` 中，以便返回时核对。
- `redirect_uri`：使用应用的第一个已登记回调地址时可省略；传入时必须与应用的已登记回调地址之一完全一致。

尚未登录本站的用户会先被要求登录。随后页面会显示应用名称、负责人（如有）以及应用将能看到的内容：用户在本站的名称、头像和角色，外加每项权限范围各一行说明。它绝不会共享用户的邮箱或密码。在用户点击「继续」之前不会发生任何操作。

</Step>
<Step>

### 完成登录并调用 `/api/v1`

用户点击「继续」后，`/authorize` 会跳转至：

```
<redirect_uri>#token=<customToken>&state=<state>
```

令牌放在 URL 片段（`#…`）中，因此绝不会通过请求地址或 `Referer` 头发送到服务器。在你的应用中：

1. 从 `window.location.hash` 读取 `token` 和 `state`，用 `history.replaceState` 清除地址栏中的 `#…`，并核对 `state` 与发出时一致。
2. 在你的应用的 Firebase Auth 实例上调用 `signInWithCustomToken(auth, token)`。此时该用户在你的项目中的 `uid` 与在 `sekaibeyond.com` 上的完全一致。
3. 从浏览器（在已登记的站点上，请求 `https://sekaibeyond.com/api/v1`）或你的服务器（`https://sekaibeyond.com/api/v1` 或 `https://api.sekaibeyond.com/v1`）调用 `/api/v1` 时，将该用户的 Firebase ID 令牌（`await user.getIdToken()`）放入 `Authorization` 请求头：

```js
const idToken = await auth.currentUser.getIdToken();
const res = await fetch('https://sekaibeyond.com/api/v1/me', {
  headers: { Authorization: `Bearer ${idToken}` },
});
const me = await res.json();
```

</Step>
</Steps>

## 令牌声明与实时检查

自定义令牌上的声明会保留在该次登录续期出的每一个 ID 令牌上：

- `app`：应用 ID（`appId`）。
- `group`：用户在本站的组别（`president`、`core-staff`、`staff` 或 `user`）。
- `eventStaff`：仅当应用拥有 `event-staff:read` 时提供。用户担任工作人员的未归档活动的 ID，没有则为 `[]`：尚未结束的活动排在前面，按开始时间从近到远排列；其后是已结束但尚未归档的活动。令牌声明的大小上限为 1,000 字节，因此如果某人担任工作人员的活动多到放不下（约 35 个），被省略的是已结束或最远的那些。[`GET /v1/me`](../api-reference/get-me.mdx) 会列出全部活动，包括已归档的活动。
- `mintedAt`：签发该次登录时的毫秒时间戳。

声明反映的是登录时的情况。当你的应用的登录所带的声明发生变化时，用户会被退出你的应用，下次登录时便会带上新的值，详见下文。

每次 `/api/v1` 调用都会实时读取用户在本站的账号：

- **退出所有设备、退出其他设备、设置新密码（修改或重置）或撤销邮箱变更**后，`/api/v1` 会立即以 `401 session-ended` 拒绝该时间点之前的登录凭证。同时会吊销用户在你的应用项目中的刷新令牌，因此其在应用中的登录会在当前 ID 令牌过期后（一小时内）结束。
- **注销账号**在账号被移除时生效，即申请注销至少 48 小时之后（期间可以取消）。此后 `/api/v1` 返回 `401 session-ended`，该用户也会从你的应用项目中删除。
- **更改用户的组别**会让其退出所有应用。**将其设为未归档活动的工作人员，或将其移出**（由管理员操作，或用户自己使用工作人员码加入）时，会让其退出所有拥有 `event-staff:read` 的应用。两种情况下都会吊销该用户在你的应用项目中的刷新令牌：其在应用中的登录会在当前 ID 令牌过期后（一小时内）结束，重新登录后便会带上新的声明。`/v1/me` 会立即返回变化，`/api/v1` 也会继续接受其当前的登录。仅修改头衔，或更改已归档活动的工作人员，不会改变任何声明，也不会让任何人退出登录。活动前大量设置工作人员时，相关用户可能需要更频繁地重新登录。
- **为应用添加或移除 `event-staff:read`** 会让所有通过彼世界账号登录该应用的人退出登录，这样他们下次登录时便会带上或不再带有 `eventStaff`。你的应用自己创建的、拥有独立登录方式的用户不受影响。
- **修改应用的权限范围或移除应用**会在 10 秒内对 `/api/v1` 生效。
- 每位用户在每个应用中每分钟最多调用 **60 次**。

在你的应用项目中吊销和删除用户需要上面的第二项 IAM 角色。无论是否授予，`/api/v1` 都会拒绝该登录。

## 决定谁可以使用你的应用

任何拥有本站账号的人都可以登录你的应用。登录只说明某人是谁，并不代表他可以使用应用。请在你自己的项目中决定这一点，例如在数据库中维护一份访问名单，并由安全规则检查：

```
function signedInWithSekaiBeyond() {
  return request.auth != null
    && request.auth.token.firebase.sign_in_provider == 'custom'
    && request.auth.token.app == '<appId>';
}

match /projects/{projectId} {
  allow read, write: if signedInWithSekaiBeyond()
    && exists(/databases/$(database)/documents/projects/$(projectId)/access/$(request.auth.uid));
}
```

规则也可以根据令牌中的 `group` 和 `eventStaff` 声明，按用户在本站的角色放行：

```
function signedInWithSekaiBeyond() {
  return request.auth != null
    && request.auth.token.firebase.sign_in_provider == 'custom'
    && request.auth.token.app == '<appId>';
}

// 在签发后 5 分钟内使用的登录，/authorize 的登录都是如此。被搁置更久的登录
// 可能带着某次变化之前的声明，而那次退出登录并未覆盖到它。
function usedPromptly() {
  return request.auth.token.auth_time * 1000 - request.auth.token.mintedAt < 300000;
}

// 本站的核心工作人员和会长。
function isCoreStaff() {
  return signedInWithSekaiBeyond() && usedPromptly()
    && request.auth.token.group in ['core-staff', 'president'];
}

// 本站某个活动的工作人员，且仅在活动进行期间。规则无法读取官网的活动，
// 因此请在你自己的数据库中保存每个活动的开始和结束时间，例如从 GET /v1/events 复制。
function staffsDuring(eventId) {
  let event = get(/databases/$(database)/documents/events/$(eventId)).data;
  return signedInWithSekaiBeyond() && usedPromptly()
    && eventId in request.auth.token.get('eventStaff', [])
    && request.time >= event.startAt
    && request.time < event.endAt;
}

match /events/{eventId}/checklists/{checklistId} {
  allow read: if isCoreStaff() || staffsDuring(eventId);
}
```

- **除登录方式外，还要检查 `app`，** 这样只有为你的应用签发的登录才算数。
- **凡是检查 `group` 或 `eventStaff` 的地方，都要检查登录是否及时使用**（`usedPromptly`）。登录令牌签发后一小时内都有效，因此在某次变化之前签发、之后才使用的令牌，会以旧的声明开始一次登录，而任何退出登录都无法覆盖它。
- **`group` 和 `eventStaff` 最多可能滞后一小时。** 发生变化时用户会被退出你的应用，但其当前的 ID 令牌在过期前仍然有效，而规则无法得知它已被吊销。如果这一小时很重要（例如需要立即收回权限），请维护你自己的访问名单，或从服务器调用 [`GET /v1/me`](../api-reference/get-me.mdx) 检查。
- **如果你的项目没有授予 `roles/firebaseauth.admin`**（见上文），变化永远不会让任何人退出你的应用，这些声明会一直保持原样，直到用户重新登录。没有该角色时，不要在规则中检查它们。

## 人员权限范围

| 权限范围 | 允许应用 |
|---|---|
| *（无）* | 为当前登录用户调用 [`GET /v1/me`](../api-reference/get-me.mdx) |
| `events:read` | [列出活动](../api-reference/list-events.mdx)和[获取活动](../api-reference/get-event.mdx)（仅限该用户在官网能看到的活动） |
| `team:read` | [列出团队名单](../api-reference/list-team.mdx)（仅限登录者为工作人员及以上时） |
| `event-staff:read` | [列出活动工作人员](../api-reference/list-event-staff.mdx)（仅限登录者为工作人员或该活动的工作人员时）；并通过 `eventStaff` 声明和 [`GET /v1/me`](../api-reference/get-me.mdx) 得知登录者担任工作人员的活动 |
