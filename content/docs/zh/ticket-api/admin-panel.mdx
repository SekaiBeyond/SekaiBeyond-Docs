---
title: 在管理后台中
description: 工作人员如何查看和处理应用创建的订单。
---

一笔订单对应一位参会者，并标有密钥的名称。它的处理方式与 HomeTown 门票相同：买家在销售方的应用中持有的就是这些门票，所以工作人员可以修改其名称、更改某张门票的票种、作废或扫码其门票，但不能重新签发或删除它。

除非订单通过 `sendEmail` 要求发送邮件，否则不会从这里发送邮件；要求了的订单会像其他参会者一样显示为已发送、排队中或未发送，「发送未发送」和「重发邮件」对它都有效。它也可能显示为「未确认」：API 正在发送时我们的邮件服务商停止了响应，所以邮件可能已发出，也可能没有。「发送未发送」会跳过这些订单；工作人员先与买家核实，如果没有收到，再用「重发邮件」发送。

使用相同邮箱的参会者导入不会覆盖它。归档活动时，它的订单会和其他参会者一起移动，API 仍能在那里找到它们。

## 退款

退款目前还不在 API 中。在此之前，由工作人员在管理后台作废已退款的门票，订单随后会将其显示为 `voided`。
