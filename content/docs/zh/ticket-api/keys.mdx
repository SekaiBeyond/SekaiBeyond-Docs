核心成员及以上可以在管理后台的「工具 > 应用」中登记应用并管理其服务器 API 密钥。工作人员组看不到这个工具，其背后的函数（`listApps`、`saveApp`、`deleteApp`、`createApiKey`、`renameApiKey`、`revokeApiKey`）也会拒绝核心成员以下的任何人。

## 已登记的应用

每项接入都始于一个已登记的应用（`apps/{appId}`）：

- **应用 ID**（`appId`）：登记应用时由本站自动生成，为 16 位小写十六进制字符，例如 `3f9c2a7e5b1d8046`。它用于登录链接，并用于将该应用的门票订单与其他应用区分开，因此无法更改，而应用名称可以修改。点击应用卡片上的「复制 ID」即可复制。
- **名称**：在列表中显示，并在用户登录该应用时展示。
- **创建者与维护者**：每个应用的卡片都会显示登记该应用的人（创建者）和负责维护它的人（维护者）。维护者是本站上的账号，最多五位，可不填，并会显示在登录页上。创建者在登记应用时确定，不必同时是维护者。
- **用户登录**（可选）：回调地址、Firebase 项目 ID 和服务账号，用于在 `/authorize` 让用户登录（见[使用彼世界账号登录](./sign-in.mdx)）。如果只是使用 API 密钥的后端服务，取消勾选即可。
- **移除应用**会立即停止该应用的登录，并在同一事务中吊销并删除它的所有 API 密钥。

## 服务器 API 密钥

在任意已登记应用的卡片上，点击「+ 新建密钥」即可在该应用下创建服务器密钥：

- 密钥只在创建时显示一次。我们只在 `apiKeys` 中保存它的 SHA-256，任何客户端都无法读取（见 [`firestore.rules`](https://github.com/SekaiBeyond/SekaiBeyond-Web/blob/main/firestore.rules)）。丢失的密钥无法找回：在旧密钥上点击「重新创建」即可在同一应用下用相同设置生成新密钥，随后吊销旧密钥。
- **新密钥在创建后几秒内生效**，而不是立即生效。在此之前它会返回 `invalid-api-key`，所以创建后马上发起的第一次调用可能需要重试。
- **吊销密钥即删除密钥。** 它会立即失效并从列表中移除，「操作记录」中保留它的名称、所属应用及首尾几个字符。过期的密钥会出现「删除」按钮，可以用同样的方式将其从列表中清除。
- 每个密钥都有**权限范围**：`events:read`、`team:read`、`event-staff:read`、`tickets:write`、`tickets:read`。
- 密钥可以限定于**特定活动**（最多 20 个），创建时从未归档的活动中选择。这些活动归档后限定依然有效，「重新创建」也会沿用它们。默认可以使用所有活动。
- **订单号按应用 ID（`appId`）分别保存。** 两个应用可以各有一笔订单 `1001`，而一个密钥只能创建和读取它所属应用的订单。同一应用下创建的所有密钥共享这些订单，因此在同一应用下替换旧密钥的新密钥仍能找到之前创建的订单。
- 每个密钥都会**过期**，有效期可选 30 天、90 天、一年（默认）或两年。
- 密钥属于该应用，而不是创建它的人。创建者卸任后密钥依然有效，任何核心成员都可以重命名或吊销它。重命名只改变列表、新订单和新记录中显示的名称：已有的订单和记录仍保留当时的名称。
- 每个密钥每分钟最多调用 **120 次**。
- 登记、修改或移除应用，创建、重命名或吊销密钥，通过密钥创建的每笔订单，以及为其发送或排队的每封邮件，都会记录在「操作记录」中。

<Callout type="error" title="密钥只能放在应用的服务器上。">
  绝不要把它放进移动应用、小程序或网页：任何人都可以把它提取出来，读取它能读取的一切，并给自己签发门票。使用密钥发起的调用永远不会返回 CORS 响应头。
</Callout>

## 密钥权限范围

| 权限范围 | 允许密钥 |
|---|---|
| `events:read` | [列出活动](../api-reference/list-events.mdx)和[获取活动](../api-reference/get-event.mdx) |
| `team:read` | [列出团队名单](../api-reference/list-team.mdx) |
| `event-staff:read` | [列出活动工作人员](../api-reference/list-event-staff.mdx)，限密钥可用的活动 |
| `tickets:write` | [创建订单](../api-reference/create-order.mdx) |
| `tickets:read` | [获取订单](../api-reference/get-order.mdx) |

应用通过密钥读取主站的数据：用户的登录凭证只说明该用户是谁。密钥按其权限范围读取数据，与谁在使用你的应用无关，因此你的应用中谁能查看这些内容，由你的应用自己决定。

缺少所需权限范围的调用会返回 `403 missing-scope`。用密钥调用关于当前登录用户的 `/v1/me` 会返回 `403 sign-in-required`，用用户的登录凭证调用其他端点则会返回 `403 api-key-required`。超出速率限制的调用会返回 `429 rate-limited`，并通过 `Retry-After` 告知需要等待的秒数。详见[错误](../api-reference/errors.mdx)。
